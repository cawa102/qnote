# ターミナルノートアプリ 機能要件統合レポート

> Obsidian、Notion、既存CLIツールの分析結果を統合し、ターミナルベースノートアプリの必須機能と優先度を定義する。

---

## 1. 調査サマリー

### Obsidian（150万+ MAU）
- **成功要因**: ローカルファースト、プレーンテキストMarkdown、双方向リンク、プラグインエコシステム
- **弱点**: 学習曲線の急勾配、プラグイン過多、同期問題、コラボレーション不足

### Notion（1億+ ユーザー）
- **成功要因**: ブロックベース構造、強力なデータベース、オールインワン、リアルタイムコラボ
- **弱点**: オフライン不可、パフォーマンス低下、Markdown不完全、データポータビリティ

### 既存CLIツール（nb, jrnl, zk, Dnote等）
- **現状**: シンプルだが機能不足 vs 高機能だがTUIなしの二極化
- **ギャップ**: リッチTUI体験、双方向リンク、統合ワークフロー、日本語対応、AI連携

| # | 機能 | 根拠 | 実現アプローチ |

| 2 | **YAML Frontmatter** | 業界標準のメタデータ管理、Obsidian互換 | `title`, `tags`, `created`, `modified` |
| 3 | **全文検索** | Notion/Obsidian共に最重要機能の一つ | SQLite FTS5 + ripgrep |

| 5 | **双方向リンク** | Obsidian最大の差別化要因、CLIツールに欠如 | `[[wikilink]]`パーサー + バックリンクインデックス |

| 7 | **デイリーノート** | Obsidianで人気、ジャーナリングの基盤 | 日付ベースの自動生成 |

## 4. 技術スタック推奨

| 領域 | 推奨技術 | 理由 |
|------|---------|------|
| **言語** | TypeScript | 型安全性、エコシステムの充実 |
| **TUIフレームワーク** | Ink + React | Reactの知見活用、コンポーネントモデル |
| **UIコンポーネント** | @inkjs/ui | プリビルトコンポーネント、テーマ対応 |
| **メタデータDB** | SQLite (better-sqlite3) | 軽量、FTS5全文検索、ゼロ設定 |
| **ファイル検索** | ripgrep (rg) | 超高速なファイル内容検索 |
| **ストレージ** | Markdownファイル + YAML frontmatter | 可搬性、Obsidian互換、人間が読める |
| **バージョン管理** | Git (simple-git) | 標準的、既存エコシステムとの親和性 |
| **CLIフレームワーク** | oclif or Commander.js | サブコマンド、ヘルプ生成、プラグイン |
| **テスト** | Vitest | 高速、TypeScriptネイティブ |
| **ビルド** | tsup | 高速バンドル、ESM/CJS対応 |
| **パッケージ管理** | npm | 広く普及、安定 |

## 7. 競合との差別化まとめ

| 差別化要素 | vs Obsidian | vs Notion | vs 既存CLIツール |
|-----------|-------------|-----------|----------------|
| **リッチTUI** | Obsidianの操作感をターミナルで再現 | キーボードネイティブの高速操作 | 既存CLIに欠如する視覚的体験 |
| **双方向リンク** | 同等の機能をCLIで | Notionのリレーション相当 | ほぼ唯一のCLI実装 |
| **シンプルさ** | プラグイン沼を回避 | 学習曲線の大幅削減 | nbの複雑さを回避 |
| **ローカルファースト** | 同等 | Notionの最大弱点を解決 | 多くが対応済み |
| **Git統合** | Obsidian Sync不要 | 不可能 | 一部対応だが深くない |
| **高速起動** | Electronより軽量 | Webアプリより圧倒的に速い | 同等 |
| **スクリプタビリティ** | プラグインより柔軟 | API依存 | Unix哲学の延長 |
