> spec.md セクション9の詳細設計。ブレインストーミングにより決定。

## 1. デザイン原則とビジュアルスタイル

### ビジュアルスタイル: モダン・グラデーション

Charmbracelet系ツール（gh CLI, gum, glamour）に倣った現代的ターミナルデザイン。

### 3つのデザイン原則

1. **ボーダーレス** — 罫線ではなく余白とインデントで構造を表現。ハードな境界線を使わず、水平ルーラー（`─`）は最小限に留める
2. **ソフトアクセント** — 強いコントラストではなく、dim/bold/色のグラデーションで視覚的階層を作る。選択状態は`●/○`のようなソフトインジケーター
3. **余白優先** — 情報密度よりも可読性を重視。各ノート項目間に空行を入れ、スキャンしやすさを確保

### カラーシステム: ANSI + True Color フォールバック

- True Color対応ターミナル: RGB値で統一感のある配色
- 非対応ターミナル: ANSI 16色に自動フォールバック
- ターミナルの背景色（ダーク/ライト）に左右されにくい設計

**セマンティックカラー:**

| 役割 | True Color | ANSI フォールバック |
|------|-----------|-------------------|
| アクセント | シアン系 | ANSI cyan (bold) |
| タグ | マゼンタ系 | ANSI magenta |
| リンク | ブルー系 | ANSI blue (underline) |
| 日付・補助 | グレー | dim |
| エラー | レッド | ANSI red |
| 警告 | イエロー | ANSI yellow |
| 選択中 | グリーン/リバース | ANSI green / reverse |

## 2. 画面構成と遷移フロー

### レイアウト: シングルペイン

1つの画面に1つの機能を全画面で表示。画面遷移はスタック型（ブラウザの「戻る」と同じモデル）。

### 画面一覧（5画面）

| 画面 | 役割 | 到達方法 |
|------|------|---------|
| コマンドパレット | ホーム。全操作の起点 | 起動時 / 任意画面で `:` |
| ノートリスト | 検索結果・一覧表示 | パレットから `recent`, `search`, `tags` 等 |
| ノートプレビュー | ノート閲覧（レンダリング済み） | リストからEnter |
| 検索 | インクリメンタル全文検索 | パレットから `search` / 任意画面で `/` |
| キャプチャー | クイックメモ（ミニエディタ） | パレットから `capture` / 任意画面で `c` |

### 遷移フロー

```
[コマンドパレット] ──recent──▶ [ノートリスト] ──Enter──▶ [ノートプレビュー]
       ◀──Esc───              ◀──Esc────

[任意画面] ──:──▶ [コマンドパレット]（オーバーレイ）
[任意画面] ──/──▶ [検索]
[任意画面] ──c──▶ [キャプチャー]
```

### ナビゲーションルール

- `Esc`: スタック内で1つ前に戻る
- `q`: どこからでもTUIを終了
- `:`: どこからでもコマンドパレットをオーバーレイ表示
- `/`: どこからでも検索を起動
- `c`: どこからでもキャプチャーを起動

### アニメーション: ミニマル

画面切替はフェードイン（50-100ms）のみ。体感速度を損なわない。

## 3. 各画面の詳細デザイン

### 3.1 コマンドパレット（ホーム画面）

起動直後に表示。Spotlight/Raycastのような「何をしたいか」から始まるランチャー体験。

```
  qnote ────────────────────────────

  > _

    new note        ノート作成
    search          全文検索
    daily           デイリーノート
    recent          最近のノート
    capture         クイックメモ
    tags            タグ一覧
    links           リンク一覧
    settings        設定

  Enter select   Esc quit
```

**振る舞い:**
- ファジーマッチ対応（`"da"` → `daily` がハイライト）
- 入力テキストがコマンドに一致しない場合、全文検索にフォールバック（`"API"` → 検索結果表示）
- マッチしたコマンドはリアルタイムでフィルタ表示
- 選択中のコマンドは `●` + アクセントカラーでハイライト

### 3.2 ノートリスト

検索結果や`recent`の結果を表示するリスト画面。

```
  Recent ────────────────────────────

  ● API設計方針
    #api  #design        Feb 27  ←3

  ○ 認証フローの整理
    #auth  #api          Feb 26  ←1

  ○ プロジェクトX概要
    #project-x           Feb 25

  3 notes

  : cmd   / search   n new   q quit
```

**各ノート項目のフォーマット（2行）:**
- **1行目**: `●/○` + ノートタイトル（選択中はアクセントカラー + bold）
- **2行目**: タグ（マゼンタ）+ 日付（dim）+ バックリンク数（`←N`、アクセントカラー）

**操作:**
- `j/k` または `↑/↓`: カーソル移動
- `Enter`: ノートプレビューへ
- `n`: 新規ノート作成
- `/`: 検索起動

### 3.3 ノートプレビュー

ヘッダーバー型メタデータ + レンダリング済みMarkdown本文。

```
  ← API設計方針
  #api  #design    Feb 27    ←3 links
  ─────────────────────────────────

  # API設計方針

  REST APIの設計についての方針を
  まとめる。

  ## 認証

  [[auth-flow]][1] を参照。
  JWTベースの認証を採用する。

  ## エンドポイント設計

  - GET /api/users
  - POST /api/users
  - GET /api/users/:id

  [[db-schema]][2] も併せて確認。

  e edit   p raw   : cmd   Esc back
```

**レンダリングルール:**
- 見出し（`#`）: bold + アクセントカラー
- コードブロック: 背景色付きボックス（dimカラー背景）
- `[[wikilink]]`: ブルー + 下線 + `[番号]` 表示
- `#tag`: マゼンタ
- リスト: インデント + `●` / `1.`
- プレビュー ↔ raw Markdownの切替: `p` キーで即時トグル

**リンク操作（Vimiumスタイル）:**
- 各 `[[wikilink]]` に自動番号付与 `[1]`, `[2]`, ...
- 数字キーでリンク先にジャンプ（スタックに積まれる）
- 9個以下: 1キー即ジャンプ
- 10個以上: `g` + 2桁入力

### 3.4 インクリメンタル検索

```
  検索 > API認_
  ─────────────────────────────────
  2 results

  ● API設計方針
    ...JWTベースの[API認]証を採用...
    #api  #design         Feb 27

  ○ 認証フローの整理
    ...[API認]証のフローを整理...
    #auth  #api           Feb 26

  ↑↓ select   Enter open   Esc cancel
```

**振る舞い:**
- 入力ごとにFTS5で即時検索、結果をリアルタイム更新
- マッチ箇所はハイライト表示（`[マッチ]` で囲い + アクセントカラー）
- ノートタイトル + マッチコンテキスト（前後の文脈）を表示
- 結果数は上部に表示
- `j/k`で結果間移動、`Enter`でプレビューへ

### 3.5 キャプチャー（ミニエディタ）

```
  Capture ──────────────────────────

  明日APIレビューを確認
  - 認証フローのテスト
  - DBマイグレーション
  _



  ──────────────────────────────────
  Ctrl+S save   Esc cancel
```

**振る舞い:**
- 基本的なテキスト入力（改行、バックスペース、カーソル移動）
- `Ctrl+S`: inbox ディレクトリに自動タイトル付きMarkdownファイルとして保存
- 保存後「Saved to inbox/2026-02-27-1430.md」と一瞬フィードバック表示
- `Esc`: 入力破棄してスタック上の前画面に戻る

## 4. ターミナルサイズ対応

シングルペインは幅に強いが、最低限の対応は必要。

| 条件 | 対応 |
|------|------|
| 幅 < 40カラム | 警告メッセージ表示 |
| 幅 40-79カラム | タグ・日付を省略、タイトルのみ表示 |
| 幅 80カラム以上（推奨） | 全情報表示 |

- **テキスト折り返し**: 自動。コードブロックは水平スクロール
- **ターミナルリサイズ**: `SIGWINCH` 検知で即時再描画

## 5. グローバルキーバインド総覧

| キー | 操作 | 有効画面 |
|------|------|---------|
| `:` | コマンドパレット | 全画面 |
| `/` | 検索 | 全画面 |
| `c` | キャプチャー | 全画面 |
| `q` | 終了 | 全画面 |
| `j/k` or `↑/↓` | リスト移動 | リスト・検索結果 |
| `Enter` | 選択/決定 | リスト・検索結果・パレット |
| `Esc` | 戻る/キャンセル | 全画面 |

| `1-9` | リンクジャンプ | プレビュー |
| `g` + 数字 | 10以上のリンクジャンプ | プレビュー |

### フッター: コンテキストヒント

各画面で使えるキーのみ表示（画面ごとに内容が変わる）。

| 画面 | フッター表示 |
|------|-------------|
| コマンドパレット | `Enter select   Esc quit` |
| ノートリスト | `: cmd   / search   n new   q quit` |
| ノートプレビュー | `e edit   p raw   : cmd   Esc back` |
| 検索 | `↑↓ select   Enter open   Esc cancel` |
| キャプチャー | `Ctrl+S save   Esc cancel` |

## 6. 設計判断の根拠

| 判断 | 選択 | 根拠 |
|------|------|------|
| ビジュアルスタイル | モダン・グラデーション | 開発者に馴染みのあるCharmbracelet系の洗練されたデザイン |
| レイアウト | シングルペイン | MVP最適。Inkとの相性◎。後からアダプティブに拡張可能 |
| ホーム画面 | コマンドパレット直起動 | 「何をしたいか」から始まるアクション志向 |
| カラー | ANSI + True Color | ダーク/ライト両対応。True Color環境では美しいRGB色 |
| ナビゲーション | スタック型 | ブラウザの「戻る」と同じ直感的モデル |
| プレビュー | ヘッダーバー型 | コンパクトなメタデータ + 本文に集中できる |
| アニメーション | ミニマル | 速度重視。50-100msのフェードのみ |
| 検索 | インクリメンタル | fzf的リアルタイム絞り込み。FTS5と相性◎ |
| フッター | コンテキストヒント | 画面ごとに使えるキーのみ。学習コスト最小 |
| Wiki Link | Vimiumスタイル番号 | 数字キー1打でジャンプ。最速のリンクナビゲーション |
| キャプチャー | ミニエディタ | 複数行メモ対応。TUIを離れずに素早くメモ |
